## 一、游戏定位

- **品类**:轻策略数值对撞闯关游戏,参考对象为 Hero Tower Wars 一类"数字大吃小"的平面地图解谜游戏广告原型
- **核心差异化**:在数值对撞基础上引入**骰子步数经济**(大富翁式资源管理)、**分叉路径决策**、**十二生肖符咒构筑系统**,把纯数值比较升级为"资源管理 + 风险博弈 + build 搭配"的复合玩法
- **评审重点**:玩法设计 · 关卡体验 · AI 驾驭力 · 迭代打磨(不看美术精细度、不看代码质量),因此系统设计以"规则清晰、可批量生成、决策密度足够撑住 50 关"为优先

## 二、核心空间结构与移动机制

### 空间结构

- 地图为**平面(2D网格)前进**结构,不做垂直分层设计,玩家在一张俯视网格地图上沿路径持续向前推进,方便 AI 批量生成关卡的可控性
- 路径以**图结构(DAG)**呈现,而非纯线性——主干路径基础上加入分叉点,分叉后的支线最终收敛回主干,不做无限发散的树状结构

### 分叉系统(四个独立可调旋钮)

| 旋钮 | 含义 | 演变节奏建议 |
|---|---|---|
| 分叉密度 | 全程分叉点数量 | 前期少(1-2个)→后期多(4-6个) |
| 分叉宽度 | 每个分叉是2选1还是3-4选1 | 前期固定2选1→后期偶尔3-4选1 |
| 步数张力 | 分叉的几条路步数是否一致 | 前期等步→中期小差距(±1-2步)→后期大差距 |
| 嵌套深度 | 分叉里是否还有分叉 | 前期0层→后期最多1层(建议设上限) |

**50关节奏参考表**:

| 关卡区间 | 分叉密度 | 分叉宽度 | 步数张力 | 嵌套 |
|---|---|---|---|---|
| 1-15 | 低(1个) | 2选1 | 等步 | 无 |
| 16-30 | 中(2-3个) | 2选1为主 | 小差距 | 无 |
| 31-42 | 中高(3-4个) | 偶尔3选1 | 明显差距 | 偶尔1层 |
| 43-50 | 高(4-6个) | 3-4选1可能出现 | 大差距 | 可能1层(高光关) |

**步数不等时的平衡原则**:步数差 ≈ 内容价值差。近路少走的步数要用更高的敌人门槛或更少的资源来"扣"回等价的东西,近路是"用信息劣势/资源劣势换时间效率",不是纯粹的免费福利。

**分叉点视野规则**:玩家站在分叉点时,可以看到每条分支**第一格**的内容,看不到分支再往后的内容——保证选择"有依据",不是纯瞎选,也不提前剧透。嵌套分叉只有真正走入该支线才显现下一层分叉。

### 移动机制

- 骰子决定玩家**每次能走的步数**,而非直接决定爬几层;相邻格子之间实际所需步数由关卡设计决定(目前demo中固定为1步/格,后续如需调整可在此基础上扩展)
- 每局初始骰子总量固定且有限,是贯穿全局的核心稀缺资源
- 步数用完前必须沿路径推进到终点击败 Boss,否则失败
- 难度调控核心杠杆:**"步数张力"**——关卡总所需步数与玩家初始步数储备的比例关系,已有精确的数学实现(见下方"已实现的难度引擎")

### 视野机制

- 玩家只能看清当前所在位置及**前方 N 格**(demo 中 VISION=6)的具体内容,更远处只显示模糊的危险等级提示,不显示具体数值
- 目的:保留探索悬念,但始终有依据可循,是"有信息的赌",不是纯瞎猜

## 三、核心资源管理:骰子 vs 数值

两种资源性质不对称,需要分开理解和调参:

- **骰子/步数**:硬预算,单向消耗,概率可精确计算,失败条件干脆(用完即败,不管数值多高)
- **数值**:检定门槛,目前设计下只涨不跌(除非引入负向机制),用于对照沿途门槛值

**核心设计原则**:两个资源的紧张感必须在大多数关卡里**同时存在**,否则会有一个资源沦为摆设(骰子太富余→退化成纯数值检定游戏;数值曲线太松→退化成纯步数规划游戏)。

分叉路径是让"资源该怎么取舍"显性化为玩家选择的最自然工具:走近路省步数但数值涨得少,走远路耗步数但数值更充裕。

**关于失败机制的最终决定**:不引入"失败瞬间紧急兑换"这类安全垫,失败就是失败,直接结束当前关卡重试。理由:失败保留真实代价,才能让符咒构筑的选择显得有分量(类似肉鸽游戏的设计逻辑),避免安全垫消解掉核心资源管理的紧张感。

## 四、格子(位置)类型框架

| 类型 | 说明 | 触发方式 |
|---|---|---|
| 普通小怪 | 基础数值对撞战斗 | 停留触发 |
| 精英怪 | 数值显著高于当期平均值,击败后有额外加成 | 停留触发 |
| Boss怪 | 每关终点战斗,固定在路径终点 | 停留触发(强制) |
| 骰子补给 | 获得额外步数资源 | 停留触发 |
| 金币补给 | 获得金币(局外购买/强化用) | 停留触发 |
| 数值道具/gain格 | 直接获得数值加成 | 停留触发 |
| 宝箱 | 开出随机结果(见下方宝箱系统) | **玩家主动选择是否开启**(掌控权在玩家手上) |
| 空格/安全格 | 无事发生 | 无 |

## 五、宝箱系统

### 设计原则

- 宝箱**分两种类型**(数值宝箱 / 骰子宝箱),开箱前玩家能看出类型,但具体结果未知
- 是否开启**完全由玩家主动选择**,不强制触发——这样宝箱从"随机事件"变成"要不要冒险"的主动决策点,是当前设计里决策密度最重要的补强点之一
- 两种宝箱结果分别围绕"数值"和"骰子"两条资源线,不引入无关维度,保持宝箱定位清晰

### 数值宝箱结果池(前期概率示例,可随难度调整)

| 结果 | 效果 | 前期概率参考 |
|---|---|---|
| 小幅增益 | 数值 +固定量(略高于普通gain格) | 45% |
| 大幅增益 | 数值永久+较大固定量 | 20% |
| 小幅debuff | 数值 -当前数值的一定比例(如10%) | 25% |
| 重创debuff | 数值 -当前数值的较大比例(如20%) | 10% |

> debuff 按当前数值的百分比计算,而非固定值,避免早期数值过低时扣成负数或扣得比例失控。

### 骰子宝箱结果池(前期概率示例)

| 结果 | 效果 | 前期概率参考 |
|---|---|---|
| +1骰子 | 直接获得1个骰子 | 40% |
| +2骰子(稀有) | 直接获得2个骰子 | 20% |
| 保底点数 | 下一次投骰保底较高点数(一次性) | 25% |
| -1骰子(debuff) | 扣除1个骰子(扣数量而非扣点数,避免归因混乱) | 15% |

### 难度节奏

前期(1-15关)好结果概率高(70%+),建立"宝箱是好东西"的信任感;中期开始debuff概率逐步上升(约30关好坏对半);后期(40+)debuff概率可反超,让宝箱变成需要认真权衡的关键决策点。

## 六、金币与武器系统

### 金币

- 沿途格子获得,**只能在关外商店消费**,不引入关内即时消费(避免打断骰子推进节奏)
- 主要用途:购买/强化武器

### 武器系统

- **每局限带 1 件武器**(单武器槽),获取方式:宝箱开出 / 关外商店用金币购买
- 效果设计原则:**尽量跨维度组合**,不做单一数值加成,让"数值"和"骰子"两条资源线互相喂养(与核心资源管理原则呼应)
- 已确定示例(前期武器):**+6点数值,击杀敌人时 30% 概率掉落一枚骰子**
- 后续设计方向参考(未定案,供发散):
  - 触发时机多样化:拾取时/战斗胜利后/进入新层时/Boss战专属
  - 转化型效果:如消耗步数换数值,或战斗胜利后减少所需步数
  - 条件触发型:如数值低于敌人时小幅自动提升,或每层首次开宝箱必定好结果
- **武器与符咒的定位区分**:武器负责"资源转化规则"与数值成长(量变),符咒负责"空间/战斗规则"的质变;避免两个系统功能重叠

### 与难度引擎的关系(重要约束)

武器**不做无限跨关卡堆叠**,采用与符咒对称的"永久收集 + 局内限量装备"结构,保证进入每一关的真实战力增幅有天花板,现有的胜率精确反解难度曲线(PLAN 系统)只需按固定装备上限做一次性校准,不需要应对无限变量。

## 七、十二生肖符咒系统

### 系统定位

- 本作最核心的差异化系统,类似构筑(build)玩法,通过击败对应生肖 Boss 获得(狗符咒教学关直接赠送)
- 效果设计目标:从早期简单的数值修饰,逐步过渡到后期"规则破格"型效果(如无视路径限制的跳跃、无视某类格子等),避免全部符咒都是数值百分比的排列组合,否则玩家会迅速算出"最优解"后固定使用,构筑乐趣枯竭
- **具体效果由设计者本人逐个设计**,以下仅提供设计维度参考,不代为决定

### 已确定的示例

| 生肖 | 效果 |
|---|---|
| 狗 | 携带狗符咒的关卡中,数值额外增加 30% |

### 设计维度参考(发散用,非最终方案)

- 数值对撞结果类:影响战斗胜负判定方式,还是影响战后数值获取比例
- 概率博弈类:更极端或更保守的赌博机制
- 资源经济类:影响步数、骰子数量、道具/金币获取效率
- 信息/视野类:扩大视野范围或精度
- 容错/风险规避类:减免陷阱、战斗失败的惩罚
- 针对性克制类:仅对精英怪/Boss生效
- 节奏改变类:跳过某类内容、改变格子判定规则、无视路径连通性的跳跃等

**规则破格型符咒(如跳跃)的关键约束**:如果引入"跳跃"这类效果,建议消耗与正常移动等量的步数(不做免费移动),保持"改变的是你能去哪,而不是你能不用付出代价"的原则,避免破坏核心资源管理的紧张感。

### 携带规则

| 关卡区间 | 携带上限 | 说明 |
|---|---|---|
| 1~15 关 | 1 个 | 仅狗符咒可选,教学阶段 |
| 16~30 关 | 2 个 | 符咒池扩充,开始有搭配空间 |
| 31~50 关 | 3 个 | 符咒池基本收集完整,组合策略成为通关核心 |

### Boss 分布节奏(建议,顺序可调)

```
第 3 关  ── 赠送【狗】符咒(教学)
第 6/10/14/18/22/26/30/34/38/42/46 关 ── 依次击败十一位生肖 Boss
第 50 关 ── 终极 Boss(年兽/十二生肖合围)
```

## 八、挑战模式(类肉鸽,新增)

### 核心规则

- 与普通模式**完全独立存档**(通关进度、符咒解锁互不影响,这是底线,避免玩家因怕清空普通模式进度而回避该模式)
- 一次性从第 1 关连续爬到底,中途任意一关失败,**符咒收集、金币、进度全部清零**,重新从第 1 关开始
- 挑战模式默认**解锁全部十二个生肖符咒的选择权**(不需要重新逐个打 Boss 解锁),核心乐趣聚焦在纯粹的 build 搭配与资源管理博弈,而非重复教学关

### 正向反馈设计

- 引入成就/荣誉标记系统:记录"最高连续通关关卡数"等纯展示性纪录,不影响数值,失败清零的是进度,不是纪录
- 达成一定关卡数可解锁专属称号/简单像素勋章类标记

### 重玩价值

- 复用现有 genLevel 生成器,每次挑战使用不同随机种子,保持难度曲线一致性(PLAN 系统本身与具体关卡内容无关),同时避免"背版"

## 九、美术风格方向

### 已确认方向:低多边形色块风(Low Poly Flat)

- 原因:demo 现有场景已经是 CSS 3D 变换构建的伪 3D 空间(perspective + rotateX + translateZ),像素点阵风格(如已尝试的泰拉瑞亚风格)是为正交 2D 视角设计的,放入带透视/旋转的场景中会产生"贴纸悬浮"的违和感
- 实现方式:tile 的 `.face` 从像素贴图改为纯色块 + 简单渐变高光(模拟切面受光),棋子/怪物做成简单几何体(菱形/六边形/圆柱体等)+ 描边,不需要任何图片资源,纯 CSS 即可实现,AI 修改成本低
- 十二生肖区分:靠**颜色编码 + 简化符号图标**区分,不需要逐个绘制生肖角色的精细造型
- 可叠加的强化方向:给数值文字加发光效果(如 `text-shadow`),敌我数值用不同颜色区分,強化"数值对撞"作为核心视觉记忆点,成本极低(现有 billboard 文字朝向摄像机的技巧已经实现,可直接复用)

## 十、已实现的难度引擎(demo 现状,供 AI 参考勿破坏)

- 核心公式:精确计算 N 个骰子点数总和的概率分布(`diceDist`),反解出每关"骰子数 D6"与"总步数 P"的组合,使理论胜率从早期约 78%-90% 平滑下降到第 50 关约 52% 左右,并带硬约束保证胜率不会随关卡推进而回升
- 路径生成:带方向权重的随机游走(`genPath`),形状参数控制"直线感"或"Z字形"走向
- 数值填配:根据累计预期数值动态生成沿途小怪门槛值,Boss 数值基于全程累计增益反推
- **重要**:后续加入分叉后,该难度引擎需要从"整关单一步数预算 P"改造为"分段计算"(分叉前一段 + 各支线 + 汇合后一段独立计算局部预算,再组合胜率),不需要推翻整套引擎,只是把"一段"变成"多段拼接"
